# 尾部风险与故障概率验证

## 目的

旧验证器只报告故障均值，容易出现“均值 0 故障”但真实执行发生故障的情况。新版本 `highfidelity_verify` 默认对同一计划运行 32 个独立验证场景，并报告分布统计。

## 验证结果

计划：`PLAN-20261008-0`，12 小时。

| 指标 | 结果 |
|---|---:|
| 平均验证利润 | 11181.30 |
| 最坏 10% 平均利润（CVaR10） | 342.52 |
| 利润 P05 / P50 / P95 | 1077.28 / 15084.01 / 15085.34 |
| 故障概率 | 37.50% |
| 故障 P50 / P90 / P95 | 0 / 1 / 1.45 |
| 最大故障数 | 2 |
| 未满足需求 P90 / P95 | 308.14 / 323.49 |
| 容量违反最大值 | 0 |

原始证据：`artifacts/tail_risk_validation.json`

## 结论

- 计划在容量可行性上是稳定的；
- 最终护盾会话的 0 故障不能写成“保证 0 故障”，尾部风险仍然存在；
- 利润和故障存在明显尾部风险；
- 历史未加护盾的干净会话在 step6 实际发生 1 次故障，处于该分布内；最终安全护盾会话实现 0 故障、实际利润 14529.53；
- 不能用“平均 0 故障”写成“保证 0 故障”；
- 正式提交应同时报告均值、P90/P95、CVaR 和最坏场景。
